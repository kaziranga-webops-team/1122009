Kaziranga House: system design

A free setup that stays fast for 500–600 members and keeps working for years. Each tool has one job, and everything sits as close to India as the free tiers allow.

Why the portal feels slow today (measured)

~0.4 sper Firestore request from India: the database is in the US, so every read crosses the world.
49 vs 3whole-collection reads vs reads with a limit. Pages download everything, then filter in the browser.
23queries that scan every event's sub-collections at once (collection groups). They get slower as events pile up.
0count queries, and React Query is installed but unused, so every page refetches everything it already had.

So the main problem is how and where data is read, not that a database is missing. Adding Redis alone would not fix it; steps 1 and 3 below do.

How to get there, in order

  1. 1

    Fix how the portal reads (no new tools, biggest win)

    • Ask only for what a page shows: add limit() and pagination to the 49 whole-collection reads.
    • Use count queries for totals instead of downloading every document.
    • Turn on React Query (already installed) so going back to a page shows its data at once.
    • Judge speed on the live site: the local dev server is always slower.
  2. 2

    Add Upstash Redis and Sentry

    • Cache what many people read and few change: registration counts, event lists, insights (for a minute or two).
    • Rate-limit sign-up, registration and upload routes against spam.
    • Sentry so errors reach you before members complain.
  3. 3

    One database, in Mumbai

    • Create a new free Supabase project in the Mumbai region (a region cannot be changed later, so pick it once).
    • Move website content there, then the portal's events and registrations from Firestore, one area at a time.
    • Set Vercel functions to Mumbai (bom1) once the data is there. Then every request stays inside India: tens of milliseconds instead of ~0.4 s.
    • Keep Firebase only for Google sign-in.

Things to watch on free tiers

Supabase pauses

A free project pauses after about a week with no requests. The website's 5-minute refresh keeps it awake while people visit; a daily GitHub Action ping covers quiet weeks.

Firestore's daily cap

50k reads a day goes fast when a page downloads whole collections for 600 members. Step 1 is what keeps you under it.

Backups

Free Supabase has no point-in-time restore. A nightly GitHub Action that exports the database to a private repo costs nothing.

Free limits change

The numbers above are typical free-tier limits as of late 2026. Check each pricing page before depending on one.
